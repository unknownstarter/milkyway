## 0. 한 줄 진단 (데이터 근거)

> **병목은 유입이 아니라 "사유를 남기고 다시 오게 만드는 것"(리텐션)이다.** 소셜/피드는 급소를 맞히지만 **공개 콘텐츠(연료)가 없어** 그냥 켜면 텅 빈다.

근거: 가입 95 중 메모 쓴 사람 19%, 최근 30일 메모 작성자 1명, 공개 메모 83%가 1명. 책 담기는 56%가 함.

**해법의 축**: (1) **Lyra 자동 질문**으로 사유를 유도하고 피드 연료를 자동 생성 → (2) **메모 피드**로 "누가 응답했다"는 돌아올 이유 제공 → (3) **발견(스토리 원·주간 추천·타인 책)**으로 살아있음 전달.

## 2. IA 확정 (탭 = 홈 · 책 · 메모 · 나)

| 탭 | 성격 | 담기는 것 |
|----|------|-----------|
| **홈** (랜딩) | 발견·큐레이션 | ① **좋아하는 책 스토리 원**(인스타 벤치마크) ② **이번 주 함께 읽는 책**(추천) ③ **다른 사람이 담은 책**(캐러셀) |
| **책** | 내 독서 도구 | 내 서재 → 책 상세 → **그 책의 메모** (구 홈의 읽는 책+메모 **이식**). 책 등록 시 Lyra 질문 생성 |
| **메모** | 소셜 피드 | **메모 남기기 + 내 메모 + 타인 공개 메모**를 한 흐름으로 |
| **나** | 프로필 | 내 정보 |

> 구 홈 스크린(읽는 책 캐러셀 + 선택 책 메모)은 **책 탭으로 이식**. 홈은 발견 전용으로 비워 살린다.

## 3. 신규 기능 (이번 방향의 핵심)

| ID | 기능 | 목적 | 메모 |
|----|------|------|------|
| **N1** | **좋아하는 책 스토리 원** (홈 상단) | 인스타 스토리처럼, 내 관심 책으로 진입점. 탭 → 그 책의 최근 메모·Lyra 질문 | "좋아하는 책"=즐겨찾기 플래그 신규 or `user_books` 활용(결정 필요) |
| **N2** | **이번 주 함께 읽는 책 추천** | "혼자가 아니다" + 공동 독서 유도 | 로직: 이번 주 많이 담긴/활동 있는 책 또는 운영자 큐레이션 |
| **N3** | **책 등록 시 Lyra 자동 질문** | 책 소개 기반으로 **사유 확장 질문**을 던져 메모 작성 유도 + **피드 연료 자동 생성** | LLM Edge Function. 톤 = **고상한 별의 목소리**(철학자·살짝 겉멋). 수동 시딩을 대체하는 엔진 |
| **F1** | **메모 피드** (메모 탭) | 내 메모 + 타인 공개 메모를 함께 | 공개 메모만(프라이버시) |

> **N3가 핵심 엔진**: 콘텐츠가 없어 피드가 못 살던 문제를, "책마다 Lyra가 질문 → 사람들이 답(메모)" 루프로 자동 해결. 메모 절벽(19%)도 프롬프트로 공략.

## 5. 릴리즈 스코프 & 순서

### 이번 배포 (Release 1) — "새 IA + 사유 엔진"
착수·배포 조건(노아 지정):
1. **디자인 시스템 정리**(Carat식 컴포지션·컴포넌트) — 선행
2. **온보딩**: 지금 등록된 책과 연결점(책 담기)
3. **새 홈**(N1 스토리 원 + N2 주간 추천 + 다른 사람이 담은 책)
4. **구 홈 이식**(읽는 책+메모 → 책 탭 / 메모 → 메모 탭)
5. **메모 피드**(F1)
6. **N2 주간 추천 로직**
7. **N3 Lyra 자동 질문**(권장 포함 — 피드 연료 엔진이라 함께 나가야 피드가 삶)
→ **배포**

### 다음 릴리즈 (Release 2+)
- **유저간 팔로우**
- 별 남기기 등 인터랙션 심화
- 별자리 맵(VISION v0.4~)

### 권장 순서 (Release 1 내부)
```
디자인 시스템(A) ─┬─→ 새 홈·메모 피드·책 이식(B) ─→ 배포
계측(E) ──────────┤
N3 엔진(C) ───────┴─→ 메모 피드 연료
```
> 판단: **N3(엔진)와 F1(피드)은 함께.** 연료 없는 피드를 먼저 켜지 않는다. 디자인 시스템은 모든 화면의 선행.

## 6. 확정된 결정 (2026-08-15)
1. **랜딩 = 홈**(발견). 홈 상단에 좋아하는 책 스토리 원(인스타 벤치마크). ✅
2. **메모 탭 유지** — 메모 남기기 + 타인 메모를 **피드로 함께**. ✅
3. **Lyra 자동 질문** — 책 등록 시 소개 기반 사유 확장 질문, 고상한 별 목소리. ✅ (수동 시딩 대체)
4. **팔로우는 다음 릴리즈.** 이번엔 주간 함께 읽는 책 추천 포함. VISION §6.2는 그에 맞춰 갱신. ✅

### 남은 소소한 결정
- "좋아하는 책"의 정의 — 즐겨찾기 플래그 신규 vs `user_books`(읽는 중) 활용
- N2 추천 로직 — 자동(활동 기반) vs 운영자 큐레이션 vs 혼합
- N3 톤 샘플 문장 확정(“겉멋”의 수위)

## 8. 구현 규율 (모든 기능 공통)
- **클린 아키텍처**: 신규 `features/<feature>/{data,domain,presentation}`. presentation은 repository만 경유. 신규 surface=신규 폴더. 기존 스키마 변경 금지(신규 조회·인덱스·테이블로).
- **의존성/실패 격리**: `AsyncValue` loading/error 분기, 섹션 단위 격리(발견/피드 죽어도 화면 안 죽음), Lyra 질문 생성 실패 시 graceful(질문 없이도 메모 작성 가능), 온보딩 스텝 실패 시 skip.
- **테스트**: repository(정렬·**공개 필터**·비공개 노출 0), provider 상태전이, 위젯 3상태(빈/에러/정상). N3 Edge Function은 프롬프트·톤·실패 폴백 테스트.

## 온보딩 확정 (2026-08-17)
- **흐름**: 닉네임 → 프로필 이미지 → **장르(선택 · 건너뛰기 가능, 추천 정렬용)** → **책 담기(주인공)**
- **목표**: 신규가 빈 서재가 아니라 **채워진 서재 + Lyra 물음**을 들고 진입 (콜드스타트 격파). "의식의 흐름으로 바로 담기".
- **장르 판단**: 카탈로그 작아(132권) 장르 게이팅은 빈약 → 장르는 **정렬에만**, 건너뛰기 가능. 주인공은 **남이 담은/메모한 실제 책 + 사회적 증거**.
- **KPI**: North Star = 온보딩 완료 시 **책 ≥ 3권 담은 신규 비율**. Primary = 완주율 · 첫 메모율(D0/D3). Guardrail = 장르 단계로 완주율 하락 없나. Leading = 담은 책 Lyra 물음→첫 메모, D1 재방문.
- **목업**: `previews/onb-genre.html` · `onb-books.html`
