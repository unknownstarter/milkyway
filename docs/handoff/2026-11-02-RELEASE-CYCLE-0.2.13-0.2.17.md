## 3. 사고 다섯 개

### A. 0.2.13 로그인 장애 (2026-10-31)
- 증상: Play 에서 0.2.13 을 받은 사용자가 Google 로그인 실패
- 원인: 앱 `.env` 에 다른 프로젝트(double-take) 의 Supabase 값이 섞인 채 빌드됐다. 처음엔 서명키 SHA 를 의심했다가 틀렸다
- 조치: 0.2.14 재빌드. `.env` 를 운영 값 3개(`SUPABASE_URL`, `SUPABASE_ANON_KEY`, `SHARE_LINK_BASE`)만 남기고, 서버용 키는 `supabase/.env` 로 이동. `scripts/check_release_env.sh` (빌드 전, 빌드 후 `--built`) + CLAUDE.md 필수 체크 (#90)
- 남은 일: 0.2.13 빌드에 섞여 나간 Anthropic API 키, double-take service role 키 교체 (마스터)

### B. 메모 상세에서 댓글을 쓰려면 홈으로 튕김 (2026-11-01)
- 증상: 아이폰에서 남의 메모에 댓글을 쓰려고 입력칸을 누르면 홈으로 튕기고, 그 메모를 다시 눌러도 바로 닫힘. 안드로이드는 멀쩡
- 원인 (로그로 증명):
  1. `didChangeDependencies` 가 키보드 프레임마다 `get-memo-by-id` 를 다시 불렀다 (2026-08-20 부터 있던 코드). 아이폰은 120Hz 라 1초 최대 94번, 안드로이드 기기는 33번
  2. Supabase 가 한 기기의 요청이 1초 약 50번을 넘으면 `429 RATE_LIMIT_EXCEEDED` (공식 문서는 함수 사이 호출만 제한한다고 적혀 있어 실제 동작과 다르다)
  3. provider 가 모든 오류를 null 로 바꿨고 화면은 null 을 "삭제됨"으로 읽어 pop. null 이 캐시에 남아 다시 들어가도 닫혔다
- "어제는 됐는데" 의 답: 서버/DB 변경 없음. 같은 날 아침 08:09, 08:11 (KST) 댓글 때도 429 가 수십 번 났지만 폭주의 마지막 응답이 우연히 200 이라 버텼다. 16:43, 23:23, 23:25 는 마지막이 429 라 튕겼다. 마스터가 남의 메모에 댓글을 단 건 그 전엔 8월 27일이 마지막이라 드러날 기회가 없었다
- 조치: #93 (메모 상세 재호출 제거, 404 만 없음) + #95 ~ #98 (아래 4절)

### C. 0.2.16 을 근본 원인 확인 전에 심사에 올림
- 마스터: "근본적인 원인도 분석 안되었으면서 그냥 올리면 돼?!!!!"
- 0.2.16 은 증상만 막은 상태였다. 원인 분석을 끝내고 앱 전체 감사 후 0.2.17 로 다시 냈다. 0.2.16 iOS 심사는 회수

### D. 0.2.17 aab 서명 누락 (2026-11-02)
- 증상: Play 가 "서명이 없다" 고 거절
- 원인: git worktree 에서 빌드하면서 `.env` 만 복사하고 gitignore 된 `android/app/key.properties`, `upload-keystore.jks` 를 빠뜨렸다. `build.gradle` 은 키가 없으면 조용히 서명을 건너뛴다. 빌드 후 검사는 `.env` 만 봤다
- 조치: 서명해 재빌드 (업로드 인증서 SHA256 `CD:83:CA:8E...74:75` 가 0.2.16 과 일치 확인). #100: 릴리즈 태스크인데 키가 없으면 빌드 중단, `--built` 가 서명 + 인증서 + 버전까지 검사

### E. 작업 위치 혼선
- milkyway 세션에서 double-take 작업을 하다 마스터가 지적 ("이거 그냥 밀키웨이 작업만 해야지!!!!!"). 홈 바로 아래에 worktree 를 만들어 폴더가 어지러워졌다
- 규칙: 프로젝트 세션은 그 프로젝트만. worktree 는 `~/milkyway/.claude/worktrees/` 안에만, 끝나면 바로 정리

## 4. 0.2.17 에서 앱 전체에 넣은 장치

전수 감사 (오류를 없음으로 바꾸는 곳, 오류에 화면을 이동시키는 곳, 생명주기 콜백의 서버 호출, 오류를 영구 캐시하는 provider, 잠금 없는 쓰기 버튼) 결과로 만들었다.

- **엣지 함수 관문** `lib/core/network/edge_function_client.dart` (#95): 앱의 엣지 함수 호출 12곳이 모두 여기를 지난다. 같은 함수 + 같은 body 동시 호출은 1번으로 합치고, 함수별 1초 8번을 넘으면 기다렸다 보내고, 429/500/502/503/504/546/네트워크/시간 초과는 최대 2번 재시도 (400ms, 1200ms). CI 가 이 파일 밖의 `functions.invoke(` 를 막는다. Supabase SDK 가 응답 헤더를 넘겨주지 않아 `Retry-After` 는 본문에 있을 때만 읽는다
- **메모 상세** (#95): 서버가 404 또는 restricted 라고 할 때만 닫힌다. 그 밖의 오류는 받은 메모를 유지하거나 다시 시도 화면
- **오류를 빈 목록으로 삼키지 않기** (#95): 공개 피드, 책 공개 메모, 내 책 메모, 숨긴 메모 목록. 빈 상태 문구 대신 오류 + 다시 시도. 쓰기 provider 캐시 제거, seen_tracker 첫 실패 영구 캐시 수정
- **로그인 유지** (#96): `getCurrentUser` 는 세션 없음, 세션 거부, 행 없음만 null. 나머지 오류는 throw. 스플래시는 재시도 후 다시 시도 화면 (로그인 화면 X), 딥링크와 온보딩 판정도 오류에서 로그인/온보딩으로 안 보낸다. 닉네임 확인 실패를 "중복"으로 속이지 않는다
- **쓰기** (#97): 메모 작성/수정, 프로필, 책 연결 실패에서 "저장됐어요"/화면 이동 없음. 삭제, 책 담기, 상태 변경 (실패 시 되돌림), 댓글 삭제/숨김/신고, 온보딩 완료, 알림 스위치 등 보내는 중 잠금. 책 저장 여부 조회 실패면 댓글 작성창을 열어 둔다 (comments_insert RLS 가 서버에서 강제)
- **분석 이벤트** (#98): 프로필 수정 화면 조회 이벤트가 키보드 프레임마다 쌓이던 것을 진입당 1번
- **서버** : `get-memo-by-id` 가 없는 메모에 500 (PGRST116) 을 주던 것을 404 로. 운영 계약 확인: 없는 id 404, 공개 200 memo, 남의 비공개 200 restricted
- 시험: 339개. 관문 26, 메모 상세 17, 인증 26, 쓰기 16 신규. 가드를 빼면 실패하는 것 확인
