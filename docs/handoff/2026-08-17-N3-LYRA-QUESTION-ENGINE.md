# N3 - Lyra 물음 엔진 설계

> **작성일**: 2026-08-17
> **목적**: 책 소개를 바탕으로 Lyra가 **사유 확장 물음**을 자동 생성 → 메모 작성 유도 + 피드 연료 자동 생성. (수동 시딩 대체 엔진)
> **상위**: `2026-08-15-ACTION-PLAN.md`(N3) · 톤은 `01-DESIGN_PHILOSOPHY.md` 개정(2026-08-17)

## 0. 왜 (한 줄)

메모 절벽(가입 95 중 19%만 메모)의 원인은 **빈 페이지 공포**. "메모 쓰세요"(빈 페이지) 대신 **답할 물음**을 주면 문턱이 낮아진다. 물음+답이 곧 같은 책 아래 피드가 된다.

## 1. 트리거 · 흐름

```
책이 books에 신규 등록(또는 첫 독자가 담음)
  → Edge Function `lyra-question` 호출 (책 title/author/description 전달)
  → 물음 1개 생성 → book_questions에 저장
  → 노출: 책 상세 "Lyra의 물음" / 홈 "지금 읽는 책" 카드 / 빈 홈 추천 카드 / 메모 탭
  → 사용자 "이 물음에 메모 남기기" → 메모 에디터(책+물음 컨텍스트) → 답(메모)
  → 같은 책 상세 "함께"에 답이 시계열로 모임
```

## 2. 톤 스펙 (2026-08-17 개정)

- **친근하고 위트있게.** "고상한 별 / 철학자 / 겉멋" 폐기. 어깨 힘 뺀 말투.
- **2~4문장, 질문은 하나.** 마지막이 물음.
- **이모지 OK** (0~1개, 남발 금지).
- **AI 금지 기호 절대 금지**: `—` `–` `·` 곡선따옴표 `…`. 따옴표는 곧은 `'` `"`.
- **"당신" 호칭 금지** (이름 호명 OK). 느낌표 절제.
- **빈 칭찬·교훈 설교 금지.** 책 내용에 실제로 근거해서 물을 것(환각 금지).
- humanizer 스킬 통과.

## 3. 샘플 물음 (물고기는 존재하지 않는다)

1. 제목부터 물고기는 없다고 선언하는 책이에요 🐟 평생 물고기를 분류한 학자를 쫓다 나온 결론이라니 좀 얄궂죠. 요즘 나를 지탱하는 이름표나 분류 중에, 사실 나 편하자고 붙인 건 없나요
2. 혼돈이 무서워서 세상을 칸칸이 나눴는데, 그 칸이 무너질 때 오히려 진짜가 보였대요. 지금 가장 무너뜨리기 싫은 내 칸은 뭔가요
3. 저자는 실패할 때마다 별을 봤다고 해요. 요즘 마음이 자꾸 기우는 밤에, 나는 무엇을 올려다보나요

> 톤 확인용. 노아 피드백으로 수위 조정.

## 4. 데이터 · 아키텍처 (기존 스키마 변경 금지, 신규로 확장)

- **신규 테이블 `book_questions`**: `id`, `book_id`(fk books), `question text`, `model text`, `created_at`. (책당 1개 활성, 재생성 이력 보존 가능)
- **Edge Function `lyra-question`**: input `{book_id, title, author, description}` → LLM 호출(프롬프트=톤스펙) → 검증(기호 필터·길이·물음 1개) → insert.
- **클라이언트**: repository 경유로 `book_questions` 조회. presentation은 Supabase 직접호출 금지.

## 5. 실패 · 폴백 (필수)

- description 없음/빈약 → 제목·저자만으로 생성 시도, 그래도 부족하면 **물음 생략**(카드 미노출). 메모 작성은 물음 없이도 가능.
- LLM 실패/타임아웃 → 조용히 스킵(홈은 "이어읽기" 카드로 폴백, 원칙: 섹션 격리로 화면 안 죽음).
- 기호 검증 실패(금지 기호 포함) → 재생성 1회, 실패 시 저장 안 함.
- 비용: 책당 1회 생성 + 캐시(book_questions). 재생성은 수동/운영자만.

## 6. 계측

- `lyra_question_generated`{book_id, ok}
- `lyra_question_shown`{book_id, surface(home/book_detail/feed/empty)}
- `lyra_question_answered`{book_id} = 물음 컨텍스트로 작성된 메모
- **핵심 KPI**: 물음 노출 → 메모 작성 전환율(N3의 성패 지표)

## 7. 구현 규율

- 클린 아키텍처: `features/lyra/`(or `memos`에 편입) data/domain/presentation.
- 테스트: Edge Function 프롬프트·기호필터·폴백. repository 조회·격리. 위젯 물음 있음/없음 2상태.
- 톤 회귀: 샘플 물음 세트로 기호·길이·"당신" 자동 검사(grep/린트).
