## 1. 코어 가치 재정의

> **밀키웨이는 "독서 후의 여운을 잡아두는 그릇이자, 그 여운에 응답하는 곳"이다.**

기존 정의(v1.0): "독서 메모 트래커" — Goodreads/책장이 이미 점유한 자리. 차별성 약함.

새 정의의 의미:
- **여운**: 책을 덮은 직후 1시간이 사유가 가장 살아있는 순간. 한국 독자의 정서적 진실.
- **그릇**: 도구이지 무대가 아니다. SNS화 함정 회피.
- **응답**: AI든 타인이든 열려있어 단계적 확장 가능.

**핵심 원리: 혁신은 더하기가 아니라 덜어내기다.** 다른 앱이 시끄러울 때 밀키웨이만 고요한 자리.

## 2. 코어 페르소나

**메인 타깃: "느리게 읽고, 사유를 쌓고 싶은 사람"**

= 사유 축적가 × 정독자 (느린 독자)

| 속성 | 내용 |
|---|---|
| 연령 | 30대 전후 |
| 직업 | 직장인 / 글 쓰는 사람 / 기획자 / 개발자 |
| 행동 | Obsidian·Notion 알지만 모바일에선 못 씀. 한 권을 오래 정독. 밑줄·여백 메모가 본질 |
| 미충족 욕구 | "내 사유를 누군가 받아주길" — 자기 메모가 *말 걸어오는* 경험 |
| 임시방편 | Readwise + 종이노트 + 인스타 책계 + 메모앱 조합 |

**자연 유입층**: 회복형 독서가 (30대 직장인 여성), 책으로 일상 회복 추구.
**제외 페르소나**: 취향 큐레이터 (Are.na·트위터 책계 유랑) — SNS화 위험으로 적극 유입 X.

### 코어 페르소나의 하루 시나리오
```
출근길 책 20쪽 → 한 문장에 멈춤
  → 밀키웨이에 문장+짧은 메모
점심 → Lyra로부터 별 하나가 도착 ("그 언어가 누군가에게 닿을 때…")
저녁 → 답신을 보며 내 사유가 한 겹 더 깊어진 채로 잠
```

핵심은 **"여운의 연장"**.

## 3. 차별화 축 3개

### 3.1 Slow AI
즉답하지 않는 AI. 30분~1시간 후 답신 (헤비 사용자는 "더 천천히" 설정으로 다음날 아침). 트레이드오프: 즉시 만족감 포기.

### 3.2 한국어·한국 정서 우선
- Pretendard 폰트, 한국 문학·번역서 정서, 도서관/사서 메타포의 한국적 친근감
- 글로벌 확장은 의도적 보류 (영어 i18n 안 함)
- 한국 독자의 *정서적 홈*이 되는 것이 목표

### 3.3 메모의 별자리화 (Constellation)
시간순·인기순 아닌 **사유의 결**로 연결되는 시각. 시그니처 뷰. 정보 검색 효율 일부 포기.

## 4. 정보 구조(IA) 진화

### 4.1 현재 IA의 진단 (v1.0)
4탭 모두 1인칭 시점. "함께 사유" 비전 기여도 평균 1.5/5 (PM 평가).
- Home: 본인 책 + 메모
- Books: 본인 책장
- Memos: 본인 메모 목록
- Profile: 본인 정보

타인이 들어올 surface area 0. 공개 메모 시스템(visibility='public')은 있으나 BookDetail에 묻혀 발견성 0 — **데드 자산**.

### 4.2 새 IA: "별자리 + 책 스레드" 이중 구조

**핵심 통찰: 피드는 흐르는 것, 사유는 고이는 것.** 흘려보내는 UI에 고이는 콘텐츠는 어울리지 않는다.

따라서 **공간(별자리 맵)** + **흐름(책 스레드)** 의 두 축으로 진화.

```
┌─────────────────────────────┐
│  ✦  Milkyway                │
│                             │
│        ✦                    │
│    ✦       ✦                │  ← 메인 surface: 별자리 맵
│        ✦       ·            │     본인 메모 = 밝은 별
│   ·         ✦               │     타인 공개 메모 = 흐린 별
│      ✦   ·                  │     Lyra 답신 = 별 사이의 빛줄기
│                             │     길게 누르면 연결선 표시
│  ─────────────────────────  │
│  오늘의 별 ✦                │  ← 하단 띠: 사유 일기
│  "고독은 ..." — 한강         │     오늘 메모 + Lyra 답신
│  └ ✦ Lyra: 사적 언어라는 ... │
└─────────────────────────────┘
       [별자리] [책] [나]      ← 3탭 (Profile = "나")
```

### 4.3 탭 정의 (목표 IA)

| 탭 | 정체성 | 콘텐츠 |
|---|---|---|
| **별자리** | 공간적 탐색 + 발견 | 본인 메모(밝은 별) + 타인 공개 메모(흐린 별) + Lyra 답신(빛줄기). 시간 필터 핀치 줌 |
| **책** | 깊이 있는 흐름 | 한 권의 책 = 한 스레드. 본인 메모 + 타인 공개 메모 + Lyra 응답이 시간 누적. (Are.na 채널 변형) |
| **나** | 본인 정보 + 설정 | 프로필, 책장 통계, Lyra 응답 설정, 결제 |

**기존 Memos 탭은 없어짐** (책 스레드에 흡수).
**기존 Books 탭은 책 스레드로 진화** (단순 그리드 → 스레드 누적).

### 4.4 점진 이행 (v1.0 → v2.0 IA)
v1.0의 4탭을 한 번에 바꾸지 않는다. 단계별 안전 이행:

```
[v17]   현재 4탭 유지 + 홈 정렬·온보딩만 변경
[v0.2]  현재 Home에 "오늘의 별" 띠 추가 (사유 일기 축소판). 익숙한 IA에 새 정서만
[v0.3]  Books 탭에 "스레드로 보기" 토글 (책 스레드 시범)
[v0.4]  별자리를 Profile 안 서브 surface로 베타 노출 (feature flag, 20명)
[v0.5]  IA 전환: 4탭 → 3탭 (별자리 메인). 사용자 600명+ 도달 시
```

핵심 안전 지표: **"메모 작성 후 그 메모를 다시 찾는 데 걸리는 시간"** — 이게 늘면 IA 실패.

## 5. Lyra — 사유의 응답자

### 5.1 정체

| 속성 | 정의 |
|---|---|
| 이름 | **Lyra** (라이라) |
| 어원 | 거문고자리. 별자리 IA와 정합. 우주적·신화적·비종교적 |
| 정체 | 사서 AI 에이전트. *별자리들 사이에서 답신을 보내는 존재* |
| 외형 | 프로필 사진 없음. 작은 ✦ 마크만 |
| 자기 노출 | 없음. "저는 ~을 좋아해요" 같은 1인칭 취향 발언 절대 X |
| 역할 | (1) 사용자 메모 답신, (2) 큐레이션 책 시드 메모 작성, (3) 책 완독 시 회고, (4) 별자리 연결 발견 |

### 5.2 톤 가이드

| 항목 | 규칙 |
|---|---|
| 어투 | 평서·반높임 ("~요" 톤) |
| 길이 | 2~4문장. **절대 5문장 넘기지 않음** |
| 형식 | 결론 X, **질문 하나**만 되돌려줌 |
| 호칭 | 사용자를 "당신"으로 부르지 않음. 이름도 안 부름. **호칭 자체를 거의 안 씀** |
| 느낌표 | 절대 사용 X |
| 이모지 | 절대 사용 X (✦ 마크는 시스템 표시) |
| 칭찬 | "좋은 메모예요" 같은 빈 칭찬 금지 |
| 책 추천 영업 | 절대 X |
| 위로 인플레 | "힘드셨겠어요" 같은 의례적 위로 X |

### 5.3 응답 예시

```
사용자 메모: "고통은 사적인 언어를 만든다."

✦ Lyra
읽고 한참 멈춰 있었어요.
사적인 언어라는 말이 길게 남네요.
그 언어가 누군가에게 닿을 때, 여전히 사적인 채로 남는지
궁금해지네요.
```

```
사용자 메모: "이번 주는 한 줄도 읽지 못했다."

✦ Lyra
읽지 못한 주에도 책은 옆에 있었을 것 같아요.
펴지 않은 책이 어떤 무게로 거기 있었는지 궁금해지네요.
```

```
사용자 메모: "왜 슬픈지 모르겠다."

✦ Lyra
(응답하지 않음. 대신 작은 별 하나만 표시. 침묵도 응답이다.)
```

### 5.4 응답 트리거

| 트리거 | 채택 여부 | 비고 |
|---|---|---|
| 즉시 답신 | ❌ | 채팅화됨. 사유 깊이 파괴 |
| **30분~1시간 지연 답신** | ✅ 기본값 | 사용자 메모 작성 후 자동 큐 |
| **사용자 명시 요청 버튼** | ✅ | "응답 받기" 버튼이 메모 하단에 작게 |
| 다음날 알림 | ❌ | 빈도 관리 어려움 (대신 "더 천천히" 설정에서) |
| **책 완독 시 회고** | ✅ 자동 1회 | "이 책에서 가장 오래 머문 문장은…" |
| **N개 메모 누적 시 주제 발견** | ✅ 월 1회 한정 | 별자리에서 연결 표시 |

### 5.5 답신 시간 설정

```
[기본 모드]   30분~1시간 후 답신 (메모 작성 후)
              → push 1회: "Lyra로부터 별 하나가 도착했어요"

[더 천천히]   설정에서 켜면 다음날 아침 답신
              → 헤비 사용자가 자기 사유 곱씹는 시간 보호
```

push 알림 **하루 1개 상한**. 알림 끄기 default 고려.

### 5.6 AI 응답의 공개 가능 여부
조심스럽게 가능. 단:
- AI 응답은 **사람 메모와 절대 동급이 아니다**. 별 모양·색·여백이 다름. ✦로 작게 표시
- 공개는 사용자 명시 동의 시만 (default OFF)
- "AI라는 사실 숨기지 않음" — 진정성 속이면 공동체 즉사
- AI는 *큐레이터·연결자*지 *동료 사유자*가 아니다. 위계 흐리지 말 것

### 5.7 학습 / 개인화
- 단기(같은 책 안): 응답 시 그 책의 이전 메모 컨텍스트 포함
- 중기(사용자 전체 메모): **톤 조정에만 사용** ("이 사용자는 짧은 응답 선호")
- 장기 파인튜닝: **하지 않음.** 60명 데이터로 의미 있는 개선 X, 한국 사용자 거부감 큼
- 설정에 "내 메모를 응답 생성에 사용" 토글 명시. OFF여도 작동

### 5.8 모델 / 비용
- **추천 모델**: Claude Sonnet 4.5 (한국어 사유 톤 품질 필요. Haiku는 진부해질 위험)
- **비용 추정** *추측*: 60명 × 메모 200개/월 × 응답률 30% = 3,600회/월. 입력 1,500 + 출력 400 토큰.
  - Sonnet 4.5 기준 월 **$10~30 수준**
  - 6,000명 도달 시 월 30~60만원 (BM 도입 시점)
- 응답 지연 허용 범위: 답신형이라 오히려 느려야 함. 큐 처리 방식
- LLM refusal 처리: "오늘은 답장이 늦어요" — 사용자에게 에러 노출 X

## 6. 비즈니스 모델

### 6.1 원칙
- **수익 최적화가 아니라 톤을 지키며 지속 가능**이 목표
- "더 쓰고 싶은데 막혔다"는 좌절 회피. "더 깊이 가고 싶을 때만 열린다"는 프레임

### 6.2 영구 금지 (Anti-Patterns)
| 항목 | 사유 |
|---|---|
| 광고 | 다크 톤 + 광고 = 회복 불가 |
| 책 제휴 수수료 (affiliate) | "그 책 추천도 돈 받은 거였어?" 영구 의심 |
| 인플루언서 초청 / 영업 | 톤 즉사 |
| 친구 초대 보상 | 톤 미스 |
| 좋아요 카운트 공개 | 수행 압박 |
| 팔로우 / 팔로워 노출 | 권력구조 발생 |
| 댓글 시스템 | 논쟁·감정노동 |
| 푸시 남발 | 우주 톤 파괴. 알림 하루 1개 상한 |
| "오늘의 인기 메모" 랭킹 | 인플루언서화 |

### 6.3 채택 BM (단계적)

```
[지금 ~ 600명]   BM 도입 X. 후원 버튼만 슬쩍 (1,000원~, 선택)
                  카피: "밀키웨이는 광고로 운영되지 않아요.
                         운영자에게 차 한 잔을 보내주실 수 있어요."

[600명+]         프리미엄 도입 — 월 4,900원 (추측 가격)
                  카피: "이번 달 사유 파트너와의 대화 20번이 끝났어요.
                         새 별이 다시 뜨기까지 7일 남았어요.
                         또는 — 더 깊이 가보고 싶다면, 먼 별을 켜세요."
                  무료 한도: 메모 무제한 + Lyra 응답 월 20회
                  프리미엄: Lyra 응답 무제한 + 부가 기능

[2,000명+]       한정 콘텐츠 (Lyra의 큐레이션 시드 메모, 작가 인터뷰) 번들

[6,000명+]       워크숍·B2B 실험 (트레바리 모델 응용)
```

### 6.4 SaaS 단어 회피
- "프리미엄 구독" → **"깊은 사유"** 플랜 / **"먼 별"** 모드
- "결제" → **"별을 더 띄우기"**
- "Pro" → 사용 안 함
- "월 4,900원" → "월 4,900원, 차 한 잔보다 조금 더"

### 6.5 BM 필수 전환점 *추측*
사용자 약 **800~1,200명** 사이. 그 전엔 LLM 비용 운영자가 흡수 가능. 그 이후엔 프리미엄 도입 압력 강해짐.

## 7. 단계별 로드맵

### v0.1.0+17 (가장 가까운 출시)
- 홈 정렬 변경 ✅ (이미 완료, RPC + provider)
- 온보딩 장르 칩 (10장르, 1~3개 선택)
- 베스트셀러 15권 프리셋 grid에서 사용자가 책 선택

## 8. 운영자(노아)의 역할

### 자동화 불가 — 사람 손 필요
- 주 5~7개 고품질 시드 메모 작성 (최소 6개월). Lyra 톤 가이드 따라서
- 큐레이션 책 150권의 베스트셀러 선정 + 운영
- Lyra 응답 톤 정기 검수 (월 1회 샘플 100개)
- 신고 검토 (현재 양이면 주 5분)
- 분기 1회 사용자 인터뷰 3명
- 200명 시점에 훌륭한 메모 작성자 5~10명에게 조용한 감사 DM (가시화 X)

### 자동화 가능
- Lyra의 책 시드 메모 작성 (사용자 큐레이션 + 운영자 검수)
- "이 책을 펼친 N명" 카운트
- 공개 메모 정렬 (최신/길이/오래 머문 순)
- 신고 1회 자동 비공개 처리 + 운영자 검토 큐

### 운영자 정체성
- **본인 얼굴/이름 노출 X**. 노아가 사라져도 별은 떠 있어야 한다
- 운영자 계정 이름 = "Lyra" (페르소나 = 사서 AI 에이전트)
- 모든 시드 메모는 Lyra 톤으로 작성·검수

## 9. 측정 지표

### 정량 (Supabase 직접 집계)
1. **공개 메모 비율** = 신규 공개 메모 ÷ 신규 전체 메모 (목표 30%+)
2. **타인 메모 1개 이상 본 세션 비율** (목표 50%+)
3. **동일 책 메모 작성자 2인 이상 도달한 책 비율** (목표 40%+) ← "함께 사유"의 가장 직접적 신호
4. **메모 작성 → 공개 전환율** (작성 직후 + 7일 내)
5. **공개 메모당 평균 노출 수** (한 메모가 평균 몇 명에게 닿는가)
6. **Lyra 응답 받기 버튼 클릭률** (메모 작성자 중 %)
7. **응답 후 다음 메모 작성까지 시간** (응답이 사유 자극에 기여하는지)
8. **메모 작성 후 그 메모 재방문 시간** (IA 건강도 — 늘면 위험)

### 정성 인터뷰 질문 (분기 1회)
- "다른 사람의 메모를 봤을 때 어떤 느낌이 들었어요?"
- "당신의 메모를 공개로 둔 / 비공개로 둔 이유는?"
- "**밀키웨이가 SNS처럼 느껴진 순간이 있었나요?**" ← 빨간불 감지용
- "Lyra의 답신이 사유에 도움이 되었나요?"
- "Lyra의 답신이 진부하게 느껴진 적이 있나요?" ← 모델·프롬프트 튜닝 신호

## 10. 위험 시나리오 / 안티패턴

### 영구 금지
- 광고, affiliate, 인플루언서, 친구 초대 보상, 좋아요/팔로우/댓글/푸시 남발
- "이건 하지 말자"는 [BM 섹션 6.2 표] 참조

### 위험 시나리오
1. **혁신 = 기능 추가 함정**. 밀키웨이 혁신은 *덜어내기*
2. **AI 과잉**. 매 메모마다 자동 응답하면 사용자가 자기 사유 멈춤 → 의탁
3. **시각적 화려함이 사유를 가림**. 별이 너무 반짝이면 텍스트 안 읽힘
4. **빈 우주 문제**. 신규 진입 시 별 3개만 있으면 황량 → 공개 메모 별을 흐리게 먼저 보여줘야
5. **BM 너무 빠르거나 늦거나**. 60명에서 도입 X, 3,000명에서 무료 유지도 X
6. **AI 친구 어색함** (한국 정서). 캐릭터화 절대 X (Lyra는 *존재*지 *캐릭터*가 아님)
7. **AI 응답 진부함** → 모델 강등 시 톤 즉사. Sonnet 4.5 이하로 내리지 말 것
8. **신규 가입자 위축**. 처음부터 다른 사람의 빛나는 메모를 보면 침묵 → **첫 메모 작성 전까지는 공개 메모 노출 최소화**. 첫 메모 후 여운 화면에서 처음 만나게 하자
9. **사유 vs 함께 톤 충돌**. 발견성 늘릴수록 SNS화 압력 ↑. 방어선: 수치 노출 최소화, 작성자 익명성 강화, 반응 인터랙션(좋아요/댓글) 없음. *읽기까지만, 반응은 자기 메모로*
10. **콜드 스타트**. 60명 → 600명 사이 콘텐츠 빈약 → Lyra 시드 메모로 채움

## 11. 시드 콘텐츠 전략 (콜드 스타트)

### 150권 베스트셀러 × Lyra 시드 메모 1개씩
- 10장르 × 15권 = 150권
- 각 책 소개(description) 기반으로 Lyra가 짧은 메모 1개 작성 (50~150자)
- 페이지 번호: 1~100 랜덤
- visibility: 'public'
- 작성자: 운영자(Lyra) 계정
- 사용자가 큐레이션 책 카드를 볼 때 "Lyra의 메모 한 줄"이 미리 보임 → **"여기엔 이미 읽고 사유한 존재가 있다"** 신호

### v17 시점 시드 메모 30~50개
- 운영자(노아)가 직접 Lyra 톤으로 작성
- 다양한 책에 분산
- Lyra가 자동 작성한 150권 메모와는 별도

### v0.2 이후
- 사용자 공개 메모가 늘어나면 Lyra 시드 비중 자연 감소
- Lyra는 *큐레이터*로 자리. 새 책이 추가되면 1개 시드 메모
