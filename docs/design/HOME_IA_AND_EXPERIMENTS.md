# 밀키웨이 홈 IA + 발견/소셜 실험 설계

> **작성일**: 2026-08-13
> **상위**: `01-DESIGN_PHILOSOPHY.md` (특히 원칙 5 고요한 즐거움 · 원칙 3 별빛 절제) · `docs/VISION_v2.md`
> **목적**: 홈을 "내 독서 도구 + 살아있는 은하수"로 재구성하기 위한 (1) 섹션 IA 정리 (2) 근시일 MVP 범위 (3) 가설·목표 지표·이벤트 정의.
> **주의 — 방향 전환**: 이 문서는 팔로우·타인 사유 노출 등 **소셜 요소**를 전제한다. VISION v2 §6.2 영구금지(팔로우/좋아요 공개)와 충돌하므로, 확정 시 **VISION 문서 갱신 필요**. 디자인 철학은 이를 "제품 결정"으로 열어두어 깨지지 않는다.

## 0. 왜 이걸 하나 — 푸는 문제

**콜드 스타트: "텅 빈 외로운 홈".** 혼자 쓰는 독서 앱의 1번 사망 원인이다. 첫 화면이 비어 있고 돌아올 이유가 없으면 죽는다. 밀키웨이는 이미 배포되어 있으나, 신규는 서재가 비어 있고 기존 유저는 "내가 남긴 것"만 보여 정체된다.

**처방**: 타인의 활동(추가한 책 · 남긴 공개 메모)을 홈과 온보딩에 주입해 앱이 **살아있다**고 느끼게 한다. 이는 (a) 활성화, (b) 유지, (c) 미래 Threads형 소셜 그래프의 씨앗 세 가지를 동시에 노린다.

---

## 1. 은하수 시각 원칙 (별자리 아님)

밀키웨이는 **은하수(Milky Way)** — 셀 수 없는 별이 강처럼 흐르는 성운의 띠다. **별자리(점을 잇는 선)가 아니다.** 지도 느낌을 주는 연결선은 쓰지 않는다.

- 사유의 "이어짐(잇기)"은 **기능**으로 존재하되, 화면에선 **선이 아니라 밀도·빛의 강·근접·흐름**으로 표현한다.
- 파생: 히어로/배경의 우주는 성운 흐름과 별 밀도로. 연결선(polyline) 금지.

---

## 2. 홈 섹션 IA (정본)

섹션을 **"누구의 것 / 무슨 일을 하나"**로 묶는다. 배치는 Carat의 **밀도 교대**를 따라 `나 → 발견 → 나 → 연결`을 번갈아 — "혼자가 아니다"를 리듬으로 느끼게.

### 2.1 섹션 인벤토리

| 씬 | 섹션 | 데이터 소스 | 하는 일(job) | 컴포넌트 | 주체 |
|----|------|-------------|--------------|----------|------|
| **A. 나의 흐름** | 이어 읽기 | 내 reading books(status) | 복귀 마찰↓ | 책 표지 캐러셀 | 나 |
| | 최근 본 · 저장한 | 내 조회/북마크 | 되찾기 | 소형 리스트/칩 | 나 |
| **B. 발견** | **다른 은하가 추가했어요** | 최근 타인이 등록한 책(공개) | 살아있음 · 서재 확장 | 표지 캐러셀 | 타인 |
| | 사유가 쌓이는 책 | 최근 메모가 달린 책 | 콘텐츠 발견 | 메모 미니 캐러셀 | 타인 |
| **C. 사유·연결** | 지금 흐르는 사유 | 타인 최근 **공개** 메모 | 사유 노출 · 소셜 씨앗 | 메모 카드 | 타인 |
| | 같은 책을 읽는 사람 | 동일 책 독자 | 사람 잇기(미래 팔로우) | 아바타 행 | 연결 |

### 2.2 배치·절제 규칙

- **내 것과 남의 것을 번갈아** 놓는다(밀도 교대). 발견을 연속 2개 이상 쌓지 않는다.
- **홈 상단을 통째로 발견에 내주지 않는다.** 최상단 발견 캐러셀 1개까지, 그 아래는 나의 흐름. → *내 독서 도구*라는 본질 방어(가드레일).
- 타인 노출은 **공개 대상만**(§5 프라이버시).
- 카운트/랭킹은 원칙 5(고요한 즐거움)에 따라 **불안이 아니라 경이**로 — 경쟁형 수치 노출 절제.

## 3. 근시일 MVP (가장 빠른 버전 — 현 디자인 시스템 재사용)

**현 컴포넌트 재활용으로 저비용·고속 구현.** 신규 화면 최소화.

| # | 기능 | 재사용 컴포넌트 | 신규 필요 |
|---|------|-----------------|-----------|
| MVP-1 | **온보딩 마지막 스텝**: "다른 은하가 최근 추가한 책"을 보여주고 내 서재에 추가 | `book_search_item` · 책 표지 그리드 · 온보딩 플로우 | 최근 등록 책 조회 RPC/쿼리(공개) |
| MVP-2 | **홈 최상단 "다른 은하가 추가했어요"**: 최근 등록 책 표지만 가로 캐러셀 | `reading_books_section`/`book_card` 캐러셀 패턴 | 홈 상단 섹션 위젯 1개 |
| MVP-3 | **"최근 메모가 남은 책"**: 최근 메모 달린 책 미니 메모 캐러셀 | `memo_card`(축소형) | 최근 메모 책 조회 쿼리 |

**구현 순서**: **MVP-1(온보딩) → MVP-2 → MVP-3.** 온보딩이 활성화 레버리지가 가장 크고 가장 싸다(책 검색 UI 이미 존재).

> 데이터: 신규 테이블 없이 기존 books/memos에서 "최근 N개(공개)" 정렬 조회로 시작 가능. 성능 필요 시 인덱스/뷰만 추가(기존 스키마 변경 금지 원칙 준수 — `REFACTORING_RULES.md`).

## 4. 가설 · 목표 지표

### 4.1 가설 (검증 가능하게)

- **H1 (활성화)** — 온보딩 마지막에 *다른 은하가 최근 등록한 책*을 노출하면, 신규의 **첫 책 추가율**과 **첫 메모 작성률**이 오른다. (빈 서재 마찰↓ + 사회적 증거)
- **H2 (유지)** — 홈 최상단에 타인 활동(추가 책 · 최근 메모)을 노출하면 앱이 살아 보여 **D1/D7 재방문**과 세션당 화면 수가 오른다.
- **H3 (발견→행동)** — 캐러셀 노출이 **책 추가 · 메모 열람**으로 전환된다.

### 4.2 지표 트리

| 층 | 지표 | 정의 |
|----|------|------|
| **Primary — 활성화** | 첫 책 추가율 | 온보딩 완료 후 24h 내 책 ≥1 추가한 신규 비율 |
| | 첫 메모 작성률 | 가입 후 D0 / D3 내 메모 ≥1 작성 비율 |
| **Primary — 유지** | D1 / D7 retention | 가입일 기준 재방문율 |
| **Secondary — 발견** | 발견 캐러셀 CTR | "다른 은하가 추가" 노출 대비 탭 비율 |
| | 발견→추가 전환율 | 캐러셀 탭 후 내 서재 추가 비율 |
| | 최근 메모 열람율 | "최근 메모" 섹션에서 메모 상세 진입 비율 |
| **Leading — 소셜 씨앗** | 타인 프로필/메모 조회수 | 미래 팔로우 도입의 선행 예측지표 |
| **Guardrail** | 온보딩 중도 이탈률 | 스텝 추가로 온보딩이 길어져 포기 늘지 않는지 |
| | 앱 이탈·톤 이탈 | 공개 노출로 인한 불안·소음 이탈 신호 |
| | 프라이버시 사고 | 비공개 콘텐츠 노출 0건(必) |

> **판정 기준(예시, 실측 후 조정)**: H1은 첫 책 추가율 **+상대 15%↑**, 온보딩 이탈 **+3%p 이내**면 채택. A/B(대조 = 발견 스텝 없음) 권장.

## 5. 이벤트 정의 (Firebase Analytics — `feature/firebase-ga-events` 기반)

| 이벤트 | 파라미터 | 시점 |
|--------|----------|------|
| `onboarding_discovery_shown` | `book_count` | 온보딩 발견 스텝 노출 |
| `onboarding_book_added` | `source='discovery'`, `book_id` | 온보딩에서 책 추가 |
| `onboarding_completed` | `added_book_count` | 온보딩 완료 |
| `home_section_impression` | `section`(other_galaxy_books \| recent_memo_books \| …) | 홈 섹션 뷰포트 진입 |
| `home_carousel_tap` | `section`, `item_id`, `position` | 캐러셀 아이템 탭 |
| `book_added` | `source`(home_other_galaxy \| onboarding \| search) , `book_id` | 서재 추가 |
| `memo_opened` | `source`(home_recent_memo \| feed \| …), `memo_id` | 메모 상세 진입 |

> 지표 트리(§4.2)는 이 이벤트들로 산출한다. 각 섹션은 `home_section_impression`을 분모로 CTR/전환 계산.

## 6. 프라이버시 · 톤 제약 (必)

1. **공개 대상만 노출.** 타인 메모는 **공개(public) 메모만** 표면화(앱에 이미 `memo_visibility_toggle` 존재 — 반드시 경유). 책 등록은 중립 정보로 노출 가능하나, 사용자 신원 최소 노출.
2. **경쟁형 수치 절제.** 좋아요·팔로워 카운트를 불안 유발형으로 전시하지 않는다(원칙 5). 노출하더라도 "경이" 톤.
3. **카피 규칙**: 이모지·느낌표·"당신" 호칭 없음. `humanizer` 스킬로 번역투 제거. (예: 섹션명 "다른 은하가 추가했어요"는 느낌표 없이 "다른 은하가 추가한 책"으로 정본화 권장 — 시스템 카피 느낌표 금지 원칙.)
